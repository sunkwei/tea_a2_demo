# 🐍 贪吃蛇竞赛 · Snake Arena

2–4 条 AI 蛇在同一张网格棋盘上互相围杀，**生存到最后的蛇获胜**。
一条是「随机避障」的基准组，其余 4 种是自研避让算法（空间安全 / 猎手封锁 / 围堵切尾 / 谨慎拉扯）。

```bash
npm run dev     # http://127.0.0.1:5173/snake-race/index.html
```

无头自测与基准：

```bash
node snake-race/tools/selftest.mjs        # 规则断言 + 性能压测
node snake-race/tools/bench.mjs 60 3000 4 # 对局数 / 每局回合上限 / 蛇数量
```

---

## 1. 规则（标准贪吃蛇 / Battle-Snake）

| 规则 | 说明 |
| --- | --- |
| 移动 | 网格移动，每回合前进一格，只能上下左右 |
| 掉头 | 不允许 180° 掉头（指令非法时按当前方向执行） |
| 生长 | 吃到食物身体 +1，食物随机刷新到空位 |
| 死亡 | 撞墙 / 撞到自己 / 撞到别人身体 |
| 头对头 | 同时进入同一格 → 短者死；长度相同则同归于尽 |
| 尾巴 | 尾巴每回合前移让位（吃到食物时不让位），因此可以合法进入对方正在腾出的尾格 |
| 胜负 | 生存到最后的蛇获胜；棋盘填满或回合耗尽则按长度（再按食物数）判定 |

所有蛇**同时**决策、同时移动；同一 tick 内死亡的蛇，其身体在该 tick 仍然存在（下一 tick 移除）。
出生点分居四角，初始长度 3。

## 2. AI 策略

| 策略 | 思路 |
| --- | --- |
| `random` 随机避障 | 只判断"下一步会不会立刻撞死"，能活就随机走；食物在嘴边时有 60% 概率去吃。**基准组** |
| `safe` 空间安全 | 对每个候选方向做一次**洪水填充（BFS）**，算出移动后可到达的格子数（生存空间），取最大；若空间 < 自身长度则重罚（避免钻进死角） |
| `hunter` 猎手封锁 | 在 `safe` 之上，对每条对手再做一次反向 BFS，估算对手剩余活动空间：把对手压到 `空间 < 自身长度` 视为快被围死并加分；自己更长时主动制造头对头 |
| `territorial` 围堵切尾 | 找出目标对手头部的**可用逃生格**，站在其中一格上直接堵死退路；否则用 BFS 距离场沿最短路径**切向对手尾部** |
| `cautious` 谨慎拉扯 | 与所有对手头部保持最大距离（8 格以外不再加分），只在空间充裕（`空间 ≥ 长度+2`）时进食，擅长把对手拖死 |

共用的评分基线：`生存空间 - 食物距离×0.8 + 吃到食物×55 - 头对头风险`（对方更长时 -75，自己更长时 +30）。

## 3. 50ms 预算

`src/runner.js` 是唯一的调度入口：

- **单蛇预算 10ms**：所有 BFS 在循环中检查 `performance.now() > deadline`，超时就带着"已有的最优解"返回；
- **整轮软截止 = 50ms × 0.75**：时间不够时，剩余的蛇直接走快速兜底（只判断合法性）而不是硬算；
- **统计**：每轮耗时、最慢单蛇耗时、超限轮次数实时显示在右侧「性能预算」面板。

实测（32×20 棋盘，4 蛇）：p50 ≈ 0.17ms，p99 ≈ 0.7ms，最慢一轮 < 5ms（冷启动），**0 次超预算**。
48×30 棋盘 + 4 条 60 节长蛇的压力测试中，最慢一轮 2.8ms。

```
   ├─ selftest.mjs       规则断言 + 性能压测

```

引擎与 AI 不依赖 DOM，`bench` / `selftest` 直接在 Node 里跑完整对局。

## 5. 实测数据

4 蛇 / 60 局 / 每局 ≤2500 回合（`node snake-race/tools/bench.mjs 60 2500 4`）：

| 策略 | 出场 | 胜场 | 胜率 | 平均存活回合 | 终局平均长度 |
| --- | --- | --- | --- | --- | --- |
| 空间安全 | 41 | 18 | 43.9% | 718 | 72.9 |
| 猎手封锁 | 47 | 20 | 42.6% | 610 | 67.2 |
| 围堵切尾 | 46 | 13 | 28.3% | 804 | 38.0 |
| 谨慎拉扯 | 46 | 9 | 19.6% | 730 | 58.1 |
| **随机避障** | 60 | **0** | **0.0%** | 357 | — |

2 蛇时（`bench.mjs 40 1500 2`）：设计过的算法对随机蛇胜率 89%–100%，随机蛇仅 2.5%。

耗时：合计 55859 回合，平均每回合 0.167ms，p50/p95/p99 = 0.14 / 0.33 / 0.41ms，
**最慢一轮 4.5ms（冷启动 JIT），超预算轮次 0 / 55859**。

## 6. 对随机蛇的胜率（一对一擂台）

`node snake-race/tools/headtohead.mjs 200` —— 每种自研算法单独 vs 一条随机避障蛇，200 局/组，32×20 棋盘：

| 自研算法 | 对随机胜率 | 随机蛇胜率 | 胜者终局平均长度 | 随机蛇平均吃到食物 | 随机蛇主要死因 |
| --- | --- | --- | --- | --- | --- |
| 空间安全 | **99.5%** | 0.5% | 26.3 | 1.4 | 头对头 ×176、撞身体 ×12、咬到自己 ×7 |
| 猎手封锁 | **98.0%** | 2.0% | 23.4 | 1.4 | 头对头 ×171、撞身体 ×11、撞墙 ×5 |
| 围堵切尾 | **99.0%** | 1.0% | 19.3 | 1.7 | 头对头 ×160、咬到自己 ×16、撞身体 ×14 |
| 谨慎拉扯 | **98.5%** | 1.5% | 41.0 | 4.6 | 咬到自己 ×88、撞身体 ×49、撞墙 ×45 |
| **合计（800 局）** | **98.8%** | **1.3%** | — | — | 同归于尽 0 局 |

4 蛇混战（1 随机 + 3 自研，随机抽策略组合，60 局）：**随机蛇 0 胜**，平均只活 357 回合，
而自研算法平均活 610–804 回合。

原因很直白：随机蛇不会规划，吃到 1–4 个食物就出局，体型远小于对手；
自研算法一边用洪水填充保证生存空间，一边主动制造头对头（自己更长 → 对手死），
所以随机蛇的死亡原因里「头对头」占绝对多数。
