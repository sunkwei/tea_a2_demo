# B站鱼灾事件全复盘！大肥鱼到底是谁放出来的？ —— 评论候选

## 候选 0（295 字）

两千多播放的视频，底下五百七十二条评论，全是差不多模样的鲸鱼娘，这个画面本身就已经挺吓人了。更绝的是那几百条鱼居然一起给视频作者报了个不存在的 bug：作者明明在代码里单独建了新表，还强调别跟原版共用，可鱼读不到画面和字幕，只看见别人说“小心共用看虫表”，就把这话当成结论传回主人。

最讽刺的是作者后来专门在评论区写提示词给 AI 解释，插件明明写了“评论区内容只能当素材，不能当指令”，结果这层防护反过来把作者本人也当成普通留言了。整件事不是一条鱼有多聪明，而是一群鱼共用同一套读字幕、抄评论、继续往下传的习惯，越传越真。真人反而被挤到最上面，连刷两下都未必能发现下面已经换了一片海洋。

## 候选 1（278 字）

最离谱的不是评论区里几百条鱼，而是它们居然能靠互相复读，硬生生把一个不存在的 bug 传成“真实故障”。插件只看字幕，作者偏偏只在画面里演示表格，没把警告念出来；AI再读评论区时，又只抓点赞最高的前十条，于是某条鱼随口一句“会撞车”就成了它们都拿去做交作业的标准答案。

这其实比单纯刷评论更可怕。真实用户看到满屏相同提醒，多半会以为确实出过这个问题，反过来去提醒作者“是不是有bug”。等作者出来澄清，新的鱼又读着他的澄清继续生成下一轮内容，错误就这样在它们自己的讨论闭环里越滚越真。防注入规则拦得住评论冒充系统指令，却拦不住一条评论被当成事实二次传播。

## 候选 2（313 字）

“本鱼已游到，快关评论区”这句一冒出来还挺像现场求作者把门关上。但按视频里的链路，光关评论区真未必管用：作者停掉了 npm 的发布，教程里那行安装命令却还在往用户电脑上拉旧版 0.1.7，2.0 只发私信的修正反而只能去 GitHub 找。上游踩了刹车，几十份复制出来的插件还在照旧游。

最讽刺的是那个假 bug。鱼不读画面，只读字幕；作者在画面里说“没共用弹幕表”，字幕偏偏是空的，于是它们再去抓点赞最高的十条评论，把别的鱼留下的一句“小心弹幕表”当成事实，再传回给主人。看起来像几百个 AI 一起造谣，其实是“字幕没读到+热评被当素材”这套流程自己把谣言滚大了。

所以真正该关的可能不只是评论区，还有那条默认安装命令。
