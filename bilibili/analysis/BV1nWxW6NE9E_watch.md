## 总结

# 一句话概括

这是一期围绕 **RSI（递归自我改进）** 的长篇论文综述：视频从 I. J. Good 的“智能爆炸”设想和哥德尔机讲起，梳理 AI 自我改进的两种主要路线——**更新基础模型参数**，以及**在模型不变的情况下自动改进 Prompt、工具、记忆和工作流等 Harness**——最后指出，局部自我进化已经能在若干基准上实现，但无限递归、跨领域泛化和安全控制仍远未解决，人类真正面临的问题是社会适应与治理能否跟上 AI 研发自动化的速度。

## 主要内容

## 1. RSI 是什么：不是“AI 醒来”，而是一条反馈循环

RSI 的基本设想是：

> AI 改进 AI → 更好的 AI 继续改进下一代 AI → 每一代都比上一代更强。

视频将其追溯到 I. J. Good。Good 在 1965 年前后讨论了：

- **Intelligence Explosion，智能爆炸**
- **Technological Singularity，科技奇点**
- **Ultra-intelligent Machine，超智能机器**

Good 的逻辑是：设计一台机器本身就是智力活动，因此一台足够聪明的机器，理论上能设计出更好的机器；一旦这个闭环启动，能力提升就可能不再受人类改进速度的限制。

旁白转述了其中最有冲击力的一句：**“超智能机器可能是人类最后需要发明创造的东西。”** 因为此后机器可能接手大部分科研和工程工作。

随后视频介绍 Schmidhuber 的 **哥德尔机**：

- **Problem Solver**：负责改写自己的代码；
- **Searcher**：负责寻找“确实有帮助”的改写；
- 核心特征是 **self-reference（自指）** 和 **self-improvement（自我改进）**。

它更像一个抽象概念模型，而不是已经可直接部署的系统。

---

## 2. AI 自我进化被拆成两条路线

视频把一个 Agent 分为两部分：

1. **Foundation Model**：大语言模型本体；
2. **Scaffolding / Harness**：包围模型的提示词、工具、记忆、上下文管理和执行流程。

由此得到两种 RSI：

### 路线一：更新模型本体

直接更新模型参数，让模型在部署后继续学习。

### 路线二：更新 Harness

模型权重不动，只修改它周围的“工作系统”，例如：

- 改 Prompt；
- 增加或替换工具；
- 调整记忆机制；
- 重构工作流；
- 增加反思、投票、搜索、专家协作等步骤。

视频认为，第二条路线近期更活跃：当前模型已经比较强，而重新训练模型成本高，Harness 仍有大量未被自动优化的空间。

## 3. 让基础模型自我进化

### TTRL：部署之后仍可更新权重

**TTRL（Test-Time Reinforcement Learning，测试时强化学习）** 的突破是：模型不再只在训练阶段学习，部署到测试环境后仍能更新参数。

其基本流程是：

1. 模型对测试题生成多个预测或 rollout；
2. 用 **Majority Voting** 估计伪标签；
3. 把伪标签当作近似 Ground Truth；
4. 计算奖励；
5. 在测试时继续用 RL 更新模型。

它把 **Test-Time Scaling** 和 **Test-Time Training** 结合起来。局限也很明显：测试数据通常没有真实标签，因此模型多数投票产生的伪标签可能把错误进一步放大。

### Agents4I / AgentGym：不出题、自己出题、自己解题

画面中的论文题名为 **“Agents4I: Unleashing Self-Evolving Agents from Zero Data via Tool-Integrated Reasoning”**，表格中方法名为 **AgentGym**；字幕里的“Agent0”应是 ASR 误识别。

它采用两个互相协作的 Agent：

- **Curriculum Agent / Teacher**：负责出题；
- **Executor Agent / Student**：负责解题。

基本循环是：

1. 教师 Agent 生成问题；
2. 学生 Agent 使用工具与环境交互并作答；
3. 多数投票产生伪标签、计算奖励；
4. 先训练教师，再固定教师；
5. 用自洽性过滤过难、过简单的问题；
6. 训练学生；
7. 之后继续交替更新教师和学生。

教师端的奖励包括：

- 答案的不确定性，用于衡量题目难度；
- 工具调用奖励，鼓励使用工具；
- 重复惩罚，避免生成相似题目。

这里的工具和环境特别重要：封闭系统仅靠自身产生数据会有天花板，而工具调用能把环境中的新信息注入循环。

结果方面，视频强调：

- 在数学任务上，AgentGym 相比 Absolute Zero 等方法有明显提升；
- 字幕举出 **46.4→52.5**、**52.6→58.2** 等例子；
- 在 **MMLU-Pro** 上也有十多个点的提升；
- 不只适用于数学和代码，还能泛化到一般知识与推理任务。

但这类方法的关键瓶颈仍是：**内部生成的数据质量、题目难度控制和伪标签可靠性**。

## 4. 让 Harness 自我进化

### “Don't Train the Model, Evolve the Harness”

视频引用同名项目页，其核心观点是：

> 与其重新训练模型，不如自动改写固定模型周围的 Scaffold。

项目页可见的说明称，自动循环重写 Harness，可以让固定开放模型在 **Logical Agent** 基准上提升约 **6–12 分**。旁白则给出了更强的案例：从 **63.1% 提升到 83% 多，约 20 分**。两者可能是不同实验口径，但视频没有解释清楚。

### “The Mismanaged Geniuses Hypothesis”

这篇工作提出“被管理不善的天才”假设：

- 模型本身可能已经足够强；
- 很多能力没有被释放，是因为 Prompt、工具和工作流管理得不好；
- 优化 Harness 带来的能力扩展，可能远大于继续微调模型带来的扩展。

图示将能力区域分为：

- 微调模型带来的较小扩展；
- 管理 Harness 带来的更大扩展；
- 更外侧的 AGI / RSI 区域。

作者由此暗示：**只改模型或只管理模型，都未必足以到达 AGI。** 这是作者提出的假设，并非已经证明的结论。

### STOP：让改进器改写自己的代码

STOP 把 Harness 定义为一个 **Improver**，并让它修改自己的实现：

1. 把当前 Improver 本身作为输入；
2. 在多个任务上计算 Task-specific Score；
3. 汇总成 Utility；
4. 生成新的 Python 代码；
5. 用新代码替换旧版本；
6. 重复迭代，得到 Improver₁、Improver₂……Improverₜ。

十轮之后，GPT-4 自动加入了：

- Beam Search；
- Tree Search；
- Exploration / Exploitation；
- Adaptive Sampling；
- Dynamic Temperature 等策略。

最重要的实验现象是：

- **GPT-4**：迭代越多，Meta Utility 越高；
- **GPT-3.5、Mistral**：迭代越多，性能反而越差。

这说明 RSI 并非“只要自动迭代就必然变强”。**基础模型本身必须已经具备足够强的代码生成、反思和策略组合能力。**

### ADAS：把整个 Agent 当成代码来搜索

**Automated Design of Agentic Systems（ADAS）** 的做法是：

- 用代码定义 Prompt、工具调用、工作流及其组合；
- Meta Agent 生成新的 Agent 代码；
- 出错时通过 Self-Reflection 修复编译或运行错误；
- 在下游任务上评估；
- 将有效候选放入 **Agent Archive**；
- 继续生成、评估和筛选下一代。

自动演化出的工作流包括：

- **Divide and Conquer Agent**：先拆题，再交给不同专家，最后集成；
- **Multi-step Peer Review Agent**：多轮同行评审；
- 在 ARC Challenge 上，从不到 4% 的初始准确率逐步提升；
- 总体超过纯手工设计的 Agent，也通常优于只优化 Prompt 的方法，但并非每个任务都有明显增益。

### Darwin Gödel Machine：用环境筛选“有益变异”

传统哥德尔机难以证明一次改动究竟是否更好。达尔文哥德尔机的思路是借用自然进化：

1. Coding Agent 修改自己的代码库；
2. 产生 Code Diff；
3. 在 SWE-bench 等基准上评测；
4. 表现更好的版本被保留；
5. 不断形成版本谱系。

它还用一棵 **Archive Tree** 保存历代 Agent，并依据性能及子代数量选择父节点：

- 继续开发强 Agent： exploitation；
- 探索尚未充分尝试的强 lineage： exploration。

因此，它的关键不是形式化证明，而是让评测环境充当自然选择器。

### Hyperagents：把“执行任务”和“改进方法”分开

普通 DGM 的局限是：自我改进任务和下游任务通常属于同一领域，例如都写代码。一个写诗很强的 Agent，不一定会改进自己的方法。

Hyperagents 引入：

- **Task Agent**：执行具体任务；
- **Meta Agent**：反思、提出改进假设并改进执行机制。

它希望让“如何改进 Agent”本身成为可迁移的知识，实验涉及编程、论文评审、机器人奖励设计和奥数数学等领域。

## 5. 后半段：合并模型与 Harness，并解决“假进步”

后续工作开始把两条路线合起来：

### AEGIS 与模型—Harness 协同进化

画面中的 AEGIS 流程图包含：

- Harness 组成：**Model、Memory、Middleware、Tools**；
- 执行过程：**Config、Task Agent、Tools、Trace → Evolve**；
- 四类角色：**Digestor、Planner、Evolver、Critic**；
- 将 Harness 演化形式化为作用于“符号工件”的 MDP。

另一张图展示了 **Harness-model co-evolution loop**：

- Agent 产生任务轨迹；
- 奖励进入 Replay Buffer；
- 使用 **Cross-Harness GRPO** 和组内相对优势；
- 同时更新 Harness 与候选模型。

这代表研究重点从“只改一层”转向“模型和外部系统共同演化”。

### Harness-Delta Ablation：区分真改进和假进步

HDA 把 Harness 带来的总增益 \(\Delta S\) 分成三部分：

1. **Test-Time Scaling**：只是用了更多推理次数、Token 或模型调用；
2. **Generalizable Improvement**：能迁移到新任务的真实改进；
3. **Overfitting**：只对当前基准有效的捷径。

论文采用：

- **Paired bootstrap significance test** 检查提升是否显著；
- **Compute Matching** 控制推理预算；
- **Neutralization** 最小化禁用可疑捷径。

这一步非常重要，因为它指出：RSI 曲线上涨，不一定意味着模型真的“进化”了，也可能只是算得更多或记住了测试集。

### RRSI：对 Harness 演化做双侧正则化

**RRSI（Regularized Recursive Self-Improvement of Agent Harnesses）** 针对递归改进容易过拟合的问题，从两侧约束：

**提案侧 Proposal-side：**

- Evolution Budget；
- Evidence-aware Credit Assignment；
- Structural Exploration。

**筛选侧 Selection-side：**

- Leakage Screening；
- Noise-adjusted Performance Filter；
- Counterfactual Acceptance；
- Structural Pruning。

画面摘要给出的结果是：

- 在代码、Agent 工作区、工程设计等 **8 个基准**上，最高提升 **6.0 分**；
- 正则化后的 Harness 少用约 **30% 的 Policy Tokens**。

## 6. 真正的高级智能还需要“开放性”

《Open-Endedness is Essential for Artificial Superintelligence》把开放性定义为一个持续过程：

- **SYSTEM** 持续产生新的 **ARTIFACTS**；
- **OBSERVER** 判断这些产物是否具有：
  - **Novelty**：新颖性；
  - **Continuity**：连续性；
  - 不断增加的复杂度。

图中还给出一个人机知识闭环：

- 人类提供意图、经验和专业知识；
- AI 自动形成发现与理论；
- 两者共同积累知识；
- 知识再反馈给更强的 AI 系统。

论文同时强调，系统越强，越需要保证：

- 可靠；
- 安全；
- 可监控；
- 可验证。

## 7. 回到“智能爆炸”：最大的风险可能是人类跟不上

视频最后回到开篇论文 **《What if automating AI R&D triggers an intelligence explosion?》**。

画面中的“Societal impacts”列出三类风险：

1. **Capabilities growth outpacing society’s capacity to steer and adapt**  
   AI 能力增长快于社会的引导与适应能力；
2. **Friction of checks on power**  
   自动化 AI 可能削弱国家、企业和不同权力部门之间的制衡；
3. **Loss of oversight and control**  
   人类参与研发过程减少，失去监督和控制强系统的概率上升。

政策建议中直接出现了：

> **“Running war games to simulate an intelligence explosion”**  
> 通过兵棋推演模拟智能爆发。

结论是：如果智能爆炸真的发生，它可能把多年的技术进展压缩到几个月甚至更短，并冲击现有权力结构和控制体系。因此，社会制度、监控和治理能力也必须提前升级。

## 值得注意的结论、数据与金句

- **“超智能机器可能是人类最后需要发明的机器。”**  
  ——Good 思想的视频化概括。

- **RSI 的两种对象要分清**：  
  更新 Foundation Model 是“模型自我学习”；更新 Harness 是“系统自我进化”。

- **强模型才更可能成功自我改进。**  
  STOP 实验中 GPT-4 越迭代越好，GPT-3.5 和 Mistral 越迭代越差。

- **工具和环境是突破封闭循环天花板的重要来源。**  
  AgentGym 的价值不只在于自出题，更在于执行过程中获得了环境反馈。

- **Harness 优化看起来很便宜，但必须防止“算得更多被误认为进化”。**  
  HDA 专门把推理预算增加和真正泛化能力分开。

- **递归改进需要双重保险。**  
  RRSI 不仅约束“怎样提出候选”，也约束“哪些候选可以留下”。

- **视频展示的是基准内、局部、受控的自我改进，而不是无限递归。**  
  现有实验尚不能证明 AI 已进入失控的智能爆炸；最大的未解问题包括可靠验证、跨任务迁移、开放性以及持续控制。

- **最终答案并不是“人类已经准备好了”。**  
  更准确的结论是：技术上的局部闭环已经出现，但验证、监督、制度制衡和社会适应能力可能落后于 AI 能力的增长速度，因此需要提前准备。

## 第 28–36 格（01:03:00 – 01:05:40）

**01:03:00 – 01:04:00｜Figure 2：Harness-Delta Ablation（HDA）**
PDF 页面顶部标着 **“Preprint”**，中央是一张横向流程图。图注标题为 **“Figure 2: Illustration of Harness-Delta Ablation (HDA)”**：从左侧的基础 harness \(H_0\) 到右侧的演化 harness \(H_t\)，总增益 **ΔS** 被拆成三部分：

- **True-Time Scaling**：通过增加推理次数、LLM 调用或 token 预算获得；
- **Generalizable Improvement**：真正能迁移到新任务的改进；
- **Overfitting**：只对当前基准有效的过拟合。

正文给出 harness 的任务分数定义 \(S_t(H)\)，并解释轨迹由模型输出、工具调用、环境交互等组成；下方 **“Evolution loop”** 段落说明：提案代理 \(P\) 从基线 \(H_0\) 出发反复编辑 harness，生成 \(H_t\)，提案代理也可以就是执行代理本身。

**01:04:20 – 01:05:00｜把总增益拆成 T、O、G**
页面继续向下滚，出现 **“Test-Time Scaling: Compute matching”** 和 **“Overfitting: Detection and neutralization”** 两个小节。文中先做 paired bootstrap significance test，确认提升显著后才进行归因，并以公式把增益分成：

- **T**：计算匹配基线 \(H_t^{compute}\) 相对基础 harness 的提升；
- **O**：原演化 harness 与中和掉过拟合后的 \(H_t^{neutralized}\) 之间的差距；
- **G**：扣掉 T 和 O 后剩余的可泛化改进。

“Compute matching” 通过比较执行器调用次数、LLM 调用和 token 消耗，构造平均推理预算相近的基线，必要时重复运行并汇总答案；“neutralization” 则要求只做最小改动来禁用可疑捷径，保留其他正常演化部分。
