### 0.2 术语

| 术语 | 含义 |
|---|---|
| **分享目标（share target）** | 能出现在别的 app 的「分享 / 用其他应用打开」选择器里的 app |

| **补发** | PC 连上后，队列里的内容自动按顺序发出 |

### 0.3 已确认决策清单（不再讨论）

| ID | 决策 |
|---|---|
| D1 | 手机端收到分享的文件/剪贴板时：**能连上 PC 就立刻传出**；**连不上就缓存** |
| D2 | 缓存上限：**最多 5 个文件 + 10 条剪贴板内容**（两个独立额度） |
| D3 | PC 端启动后显示**二维码**；手机用 a2_share 扫码即完成配对并连上 PC。**二维码以 PNG 形式导出**（终端 ASCII 不做） |
| D4 | a2_share 是**分享目标**（在微信等 app 里选「用 a2 分享」，微信内走「用其他应用打开」路径） |
| D5 | 本版本**不做 PC → 手机**反向推送 |
| D6 | 手机端做**独立 app**（不依赖 tea_a2 的 `liba2.so` / NDK） |
| D7 | **仅 Wi-Fi 回传**；手机**离开 Wi-Fi 作用域**后必须**重新扫码**才能再连 PC（配对按 Wi-Fi 会话作废） |
| D8 | PC 端是**独立 CLI 程序**（不依赖 tea_a2 进程），与已有 tea_a2(8383) 共存 |
| D9 | 代码落位 `tea_a2_demo/a2-share/`；本机只做需求分析，开发在另一台机器 |

## 1. 背景与目标

### 1.1 背景

手机与电脑之间传文件，目前的常规路径是「网盘 / 聊天软件 / 数据线」。这些路径都要账号、要在手机上多点几步、文件大了就卡。手机上刚收到的文件（微信里的文档、刚截的图）想赶紧落到电脑上时，最快的办法是**同一个 Wi-Fi 下的一键直传**。

本项目做两个小东西：

- **手机端 `a2_share`（独立 Android app）**：出现在系统分享面板里，把文件或剪贴板内容交给 PC。
- **PC 端 `a2_share`（独立 CLI）**：启动后出示二维码，手机扫一下就连上，之后发来的文件与剪贴板自动落地。

### 1.2 目标与成功标准

| ID | 目标 | 成功标准 |
|---|---|---|
| G1 | 分享即达 | 手机上任何能发起「分享」的内容，**1 次点击 + ≤ 5 秒**出现在 PC 上（不含大文件传输耗时） |
| G2 | 剪贴板可用 | 手机复制的文字/图片，PC 端能**直接用**（文字进 PC 剪贴板、图存盘并可选进剪贴板） |
| G3 | 不丢数据 | PC 不在线时内容**不丢**，进队列等 PC；PC 一上线自动补发 |
| G4 | 零门槛 | PC 端一条命令进入接收态；手机扫码即连，无需配置 IP/端口/账号 |
| G5 | 可复现 | 另一台机器上按本文档能独立完成开发与验收 |

### 1.3 设计原则

1. **可靠性优先**：内容**先落盘再发送**；任何一步失败都回队列，不丢数据。
2. **仅局域网**：只走 Wi-Fi，不做公网暴露、不做云端中继。
3. **连接是会话制的**：凭据跟 Wi-Fi 会话、PC 进程生命周期绑定；离开作用域即作废（宁多扫一次码，不留后门）。
4. **最小依赖**：手机端不依赖 tea_a2 / NDK / Google Play 服务；PC 端不依赖 tea_a2 进程。
5. **隐私克制**：剪贴板只在用户**主动触发**时读取；不写内容日志；缓存可一键清空。

- **PC → 手机**反向推送（D5）

- 云端中转、账号体系、远程服务端
- 跨网段 / 蜂窝回传（只走 Wi-Fi）
- 微信或企业微信的**内部消息、聊天记录、通讯录**读取
- 文件夹整体同步、双向自动同步、版本冲突合并
- PC 端文件预览 / 编辑（tea_a2 已有文件浏览，够用）
- 手机端「把内容分享给微信/企微/WPS」的**出口**能力（本版只做入口 / 分享目标）

## 3. 用户与场景

### 3.1 角色

| 角色 | 描述 |
|---|---|
| 手机用户 | 在手机上收到文件 / 复制了内容，想让它出现在电脑上 |
| PC 用户 | 在电脑上工作，希望手机发来的内容自动落到本地 |

### 3.2 主流程

```
① 一次性准备
   PC:  跑 `a2_share` → 生成 ~/.tea_agent/a2_share/qr.png → 打印路径（可选自动打开）
   手机: 打开 a2_share →「扫码连接 PC」→ 相机对准屏幕上的二维码 → 识别 → 显示「已连接 PC-xxx」
        （此后同一 Wi-Fi 会话内自动保持连接）

② 日常使用（手机在线、已连接）
   手机: 微信里收到一个 docx →「用其他应用打开」→ 选 a2_share → 确认条「发送」→ 立刻传出
   手机: 复制了一段文字 → 打开 a2_share →「发送剪贴板」→ 立刻传出
   PC:   文件落到 ~/Downloads/a2_share/；文字进 PC 剪贴板 + 桌面通知

③ 日常使用（PC 不在线 / 非 Wi-Fi）
   手机: 分享 → 提示「已缓存，将在 PC 在线后发送」→ 队列里排队
   PC:   启动 a2_share → 手机自动重连 → 队列内容自动补发（顺序 FIFO）

④ 离开 Wi-Fi 之后
   手机: 切到蜂窝 / 断开 / 换 AP → 连接与凭据立即作废 → 状态显示「已离开 Wi-Fi，需重新扫码」
   手机: 回到 Wi-Fi → 必须重新扫码 → 连上 → 缓存内容自动补发
```

### 3.3 用户故事

| ID | 故事 |
|---|---|
| US-1 | 作为手机用户，我在微信里收到一个文件，想点两下就把它弄到电脑上，而不是先传网盘。 |
| US-2 | 作为手机用户，我复制了一段话，希望电脑上能直接粘贴出来。 |
| US-3 | 作为 PC 用户，我希望我执行一个命令后它就在那儿等着，手机发来的东西自己落好盘、提醒我。 |
| US-4 | 作为第一次用的用户，我希望扫一下 PC 上的码就能连上，不用问「IP 是多少、端口是多少」。 |
| US-5 | 作为用户，我希望 PC 不在的时候我的内容不会丢，而是排队等我回来。 |
| US-6 | 作为用户，我离开 Wi-Fi 再回来时，希望它明确告诉我「要重新扫一下」，而不是默默失败。 |
| US-7 | 作为用户，我希望在发出去之前能看见「要发什么」，误触不会把私密文件推走。 |
| US-8 | 作为用户，我希望别人家 Wi-Fi 上的设备不能往我电脑里塞文件。 |

## 4. 功能需求

### 4.1 手机端（FR-P）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-P01 | 以**分享目标**身份注册：`ACTION_SEND`（单文件 / 文本 / 图片）与 `ACTION_SEND_MULTIPLE`（多文件）；MIME 需覆盖 `*/*` 与常见办公/媒体类型（pdf、doc(x)、xls(x)、ppt(x)、txt、zip、apk、图片、音频、视频） | P0 |
| FR-P02 | 收到的 `content://` URI **先复制到 app 私有目录**再处理（不申请长期读权限、不长期持有 URI 授权） | P0 |
| FR-P03 | 分享进来后弹**确认条**：文件名 / 大小 / 类型 / 目标 PC；点「发送」才传；可关闭该确认 | P0 |
| FR-P04 | 「发送剪贴板」按钮：读当前剪贴板 → 文字或图片 → 发给目标 PC | P0 |
| FR-P05 | 剪贴板图片取不到时（Android 10+ 权限、URI 失效、app 只存了路径）→ 明确人话提示，并建议「先保存到相册再分享」 | P0 |
| FR-P06 | 队列列表：每条显示 类型 / 名称 / 大小 / 入队时间 / 状态（待发 / 发送中 / 已发 / 失败 / 已失效 / 已过期） | P0 |
| FR-P07 | 队列操作：单条重发 / 删除 / 取消；剪贴板队列「一键清空」 | P0 |
| FR-P08 | 传输进度：百分比 + 速度 | P0 |
| FR-P09 | **扫码连接界面**：相机预览 + 识别 + 校验协议版本 + 协议错误提示 | P0 |
| FR-P10 | **短码兜底**：无法扫码 / 无相机 / 权限被拒时，可手动输入 PC 显示的 6 位短码完成同一套配对 | P0 |
| FR-P11 | 记录**多台 PC**（地址 + 凭据 + 名称）；发送目标默认 = 最近一次成功连上的那台；本次分享可临时切换目标 | P1 |
| FR-P12 | 前台服务 + 常驻通知，传输期间不被系统回收；息屏后仍能完成传输 | P0 |
| FR-P13 | 「后台设置」引导页：跳转厂商省电策略 / 电量优化豁免 / 通知权限（三步都点过才算完成） | P0 |
| FR-P14 | 主界面显式显示当前连接状态：`未配对` / `已连接（PC 名称）` / `已离开 Wi-Fi，需重扫` / `当前非 Wi-Fi` | P0 |
| FR-P15 | **仅 Wi-Fi**：当前网络不是 Wi-Fi 时**不发起任何连接尝试**，分享一律进缓存并提示「当前非 Wi-Fi，已缓存」 | P0 |
| FR-P16 | **离开 Wi-Fi 作用域**检测（换 AP / 换 SSID / 断开 / 切蜂窝）→ 立即作废当前配对凭据与地址，退回 `未配对`；**队列内容不受影响** | P0 |
| FR-P17 | 文件名原样保留（中文 / 空格 / emoji 不乱码、不截断） | P0 |
| FR-P18 | 通知渠道：传输完成 / 传输失败 / PC 连接成功 / 缓存淘汰 / 需要重新扫码 | P0 |
| FR-P19 | 隐私：剪贴板内容**不写日志**；队列条目存 app 私有目录 | P0 |
| FR-P20 | 首次使用引导：申请相机权限、说明「只走 Wi-Fi」、说明「离开 Wi-Fi 要重扫」 | P0 |
| FR-P21 | 应用显示名 `a2_share`；包名建议 `com.tea.a2share`（包名不能含下划线） | P0 |
| FR-P22 | 断网 / PC 掉线时传输中断 → 自动重试 3 次（指数退避）→ 仍失败则**回队列**（不占新额度） | P0 |
| FR-P23 | 大文件断点续传：重连后从中断处继续 | P0 |

### 4.2 PC 端（FR-C）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-C01 | 独立 CLI 程序 `a2_share`；`a2_share` 启动进入接收模式，`Ctrl-C` 退出 | P0 |
| FR-C02 | 启动流程：加载/生成身份 → 监听端口（**默认 8899**，与 tea_a2 的 8383 不冲突）→ **生成二维码 PNG** → 打印 PNG 路径、监听地址、短码 | P0 |

| FR-C04 | 二维码内容必须包含：协议版本、PC 设备名、地址（主机名 + IP）、端口、**会话凭据**、生成时间戳。**载荷尽量短（≤ 60 字节）**，保证图案大、一次扫中 | P0 |
| FR-C05 | **会话凭据**：PC 每次启动生成新的会话凭据并覆盖 `qr.png`；凭据只在本进程 + 本 Wi-Fi 会话内有效 | P0 |
| FR-C06 | 接受扫码配对：校验会话凭据 → 登记设备（昵称 / 系统版本 / 型号）→ 回执给手机 | P0 |
| FR-C07 | 短码：与二维码同源的一次性 6 位码，供手动输入兜底；用过后失效 | P0 |
| FR-C08 | 文件落盘：默认 `~/Downloads/a2_share/`（`--dir` 可改）；**同名不覆盖**，自动加 `(1)` / `(2)` | P0 |
| FR-C09 | 剪贴板**文字** → 写系统剪贴板 + 桌面通知 | P0 |
| FR-C10 | 剪贴板**图片** → 存为 `.png` 到接收目录 + 通知；可选同时写进剪贴板 | P0 |
| FR-C11 | 写剪贴板失败（如 Linux 无 `xclip`/`wl-copy`、Wayland 限制）→ **降级为只存文件**并明确提示，不报错终止 | P0 |
| FR-C12 | 桌面通知（可 `--no-notify` 关）+ 终端输出 + 日志文件（`~/.tea_agent/a2_share/a2_share.log`） | P0 |
| FR-C13 | 接收历史：时间 / 来源设备 / 名称 / 大小 / 结果，**只记元数据不记内容**；滚动保留最近 100 条（`--history` 查看） | P1 |
| FR-C14 | 检测到本机 IP 变化 → 重新生成二维码 PNG 并在终端提示「地址已变，请重新扫码」 | P0 |
| FR-C15 | 与已有 tea_a2(8383) **共存**：独立端口、独立进程，不修改 tea_a2 任何配置与接口 | P0 |
| FR-C16 | `a2_share --selftest`：自检端口可监听 / 凭据可生成 / 二维码 PNG 可生成 / 落盘目录可写 / 剪贴板可写；打印结果并以退出码 0/1 表示 | P0 |
| FR-C17 | `a2_share --reset-identity`：作废当前会话凭据并重新生成二维码 | P0 |

### 4.3 配对与安全（FR-S）

| ID | 需求 |
|---|---|
| FR-S01 | **未配对的设备一律拒绝**（连接层直接拒绝，且不落盘、不进历史） |
| FR-S02 | 凭据有效期 = **本 PC 进程生命周期 ∩ 本 Wi-Fi 会话**；任一失效即需重新扫码 |
| FR-S03 | 二维码等同密码：PC 端提供 `--reset-identity` 一键作废；文档提示不要把二维码截图外传 |
| FR-S04 | 传输内容**不经任何第三方服务器**，全程点对点 |
| FR-S05 | 落盘隔离在专用目录；收到的文件**不自动执行、不自动解压** |
| FR-S06 | 不做公网暴露、不做中继；PC 只在局域网可达 |
| FR-S07 | 日志与历史**只记元数据**，不记剪贴板正文与文件内容 |

### 4.4 缓存与队列（FR-Q）

| ID | 需求 |
|---|---|
| FR-Q01 | 两个**独立额度**：文件 **5** 个、剪贴板 **10** 条，分别计数，互不占用 |
| FR-Q02 | 淘汰策略 **FIFO**（先进先出）；新条目入队时若超额度，挤掉**最旧**的一条 |
| FR-Q03 | 淘汰必须**通知用户**（不静默丢数据） |
| FR-Q04 | 容量护栏：单文件 ≤ **100 MB**、文件缓存总量 ≤ **500 MB**；超限条目**拒绝缓存并明确提示**「文件过大，未缓存」 |
| FR-Q05 | 剪贴板缓存总量 ≤ 10 MB（条数为主，体积可忽略） |
| FR-Q06 | 缓存落在 app 私有目录；**启动时自检清单**，文件已被系统清理的条目标记「已失效」并提示 |
| FR-Q07 | **TTL**：剪贴板条目默认 **24 小时**过期；文件条目默认 **7 天**过期；过期条目不再自动补发，列表标灰；TTL 可配置 |
| FR-Q08 | **自动补发**：连接建立后按 FIFO 顺序自动补发；补发失败重试 3 次，仍失败则留在队列并提示 |
| FR-Q09 | 队列条目**跨 Wi-Fi 会话保留**：离开 Wi-Fi 不清队列 |
| FR-Q10 | 计数口径：**发送中 / 待重试的条目占用额度**；只有真正送达才释放 |
| FR-Q11 | 补发可整体暂停 / 单条跳过（用户在场时不想被旧内容打扰） |
| FR-Q12 | 队列落盘结构需可恢复：App 被系统杀死后重启，队列状态与内容不丢 |

### 4.5 连接生命周期 · Wi-Fi 会话模型（FR-L）

| ID | 需求 |
|---|---|
| FR-L01 | 连接模型：**PC 监听、手机主动连接**（手机换网不影响 PC 侧地址） |
| FR-L02 | 手机在配对成功后与 PC 保持连接并有心跳；PC 端显示「已连接设备」 |
| FR-L03 | 分享发生时判定「能连上」：对已配对 PC 做**短超时探测（≤ 2 秒）**；能连 → 立即传出；不能 → 进队列 |
| FR-L04 | 判定为「不在同一 Wi-Fi 作用域」→ 凭据作废 + 地址清空 + 状态提示「已离开 Wi-Fi，需重新扫码」 |
| FR-L05 | 重新扫码成功 → 建立连接 → **自动补发**队列内容 |
| FR-L06 | 同一 Wi-Fi 会话内、**PC 进程未重启**时，PC 掉线恢复后手机**自动重连**（无需重扫） |
| FR-L07 | **PC 进程重启** → 会话凭据轮换 → 手机需**重新扫码**（二维码 PNG 已刷新） |
| FR-L08 | 目标 PC 不可达且无可用备选 → 进队列，并提示「PC 未连接，已缓存」 |

## 5. 验收标准

> 统一在**真机 + 真 PC** 上跑；每条留下截图或日志作为证据。

### 5.1 分享目标与文件传输

| ID | 场景 | 期望 |
|---|---|---|
| AC-01 | 系统「文件」app 选一个 5 MB 的 PDF → 分享 → 选 a2_share | 5 秒内 PC 的 `~/Downloads/a2_share/` 出现该文件，**md5 与源一致** |
| AC-02 | WPS 的 `.docx`、相册的 `.jpg`、下载目录的 `.zip` 各分享一次 | 均落地且字节一致 |
| AC-03 | 微信里收到文件 →「用其他应用打开」→ 选择器里出现 a2_share → 选中 | PC 收到该文件，md5 一致。**若微信不列出 a2_share**：记为已知限制，写进 README，并验证替代路径（微信 → 转发到文件助手/收藏 → 系统文件 app → 分享 → a2_share） |
| AC-04 | 一次分享 3 个文件 | 3 个全部落地，文件名不串、不覆盖 |
| AC-05 | 文件名含中文 / 空格 / emoji | PC 端文件名不乱码、不截断 |
| AC-06 | PC 已有同名文件 | PC 自动改名 `x (1).pdf`，原文件不变 |
| AC-07 | 传 1 GB 文件 | 双端有进度百分比；中断（断网 / 杀进程）后恢复能续传，最终 md5 一致 |
| AC-08 | 传输中手机**息屏** 5 分钟 | 传输仍完成（需前台服务 + 已按 FR-P13 设置省电策略） |

### 5.2 剪贴板

| ID | 场景 | 期望 |
|---|---|---|
| AC-09 | 手机剪贴板有 500 字文字 → 点「发送剪贴板」 | PC 剪贴板内容逐字相同（含换行、emoji），PC 收到桌面通知 |
| AC-10 | 手机剪贴板是图片 → 点「发送剪贴板」 | PC 收到目录出现可打开、尺寸正确的 `.png`，并按设置进入 PC 剪贴板 |
| AC-11 | 剪贴板里没有图片 / app 只给了路径 | 手机端明确提示「取不到图片，请先保存到相册再分享」，不静默失败 |
| AC-12 | 剪贴板内容 | 不出现在任何日志文件里 |

### 5.3 配对与连接生命周期

| ID | 场景 | 期望 |
|---|---|---|
| AC-13 | PC 执行 `a2_share` | 生成 `~/.tea_agent/a2_share/qr.png` 并打印路径 + 6 位短码 + 监听地址 |
| AC-14 | 手机 a2_share →「扫码连接 PC」→ 相机对准屏幕上的二维码 | ≤ 5 秒显示「已连接 PC-xxx」；PC 终端出现「设备已连接」 |
| AC-15 | 无相机 / 权限被拒 | 短码手动输入可完成同样的配对 |
| AC-16 | 配对后再次分享文件 | **不需要再扫码**，直接传出 |
| AC-17 | **PC 进程重启**（同一 Wi-Fi） | 二维码 PNG 刷新；手机自动重连**失败**并提示「请重新扫码」；扫新码后恢复 |
| AC-18 | 同一 Wi-Fi 内 **PC 掉线（非重启）后恢复** | 手机**自动重连成功**，无需重新扫码 |
| AC-19 | PC 换 IP 后重启 | 手机提示「PC 地址可能已变，请重新扫码」；扫新码后恢复 |

### 5.4 离线缓存与补发

| ID | 场景 | 期望 |
|---|---|---|
| AC-20 | 断开 Wi-Fi，连续分享 3 个文件 | 手机提示「已缓存，将在 PC 在线后发送」；PC 启动后自动收到这 3 个文件，顺序 FIFO，md5 一致 |
| AC-21 | 断开 Wi-Fi，连续分享 **7** 个文件 | 只缓存最新 5 个，最早 2 个被淘汰且**有通知**；PC 最终收到 5 个 |
| AC-22 | 断开 Wi-Fi，连续发送 **12** 条剪贴板 | 只保留 10 条（剪贴板额度独立，不占文件额度） |

| AC-26 | 手机 App 被系统杀死后重启 | 队列内容与状态仍在，未丢 |
| AC-27 | 手机切到蜂窝 | 分享 → 提示「当前非 Wi-Fi，已缓存」；**不发起任何连接**（日志/抓包确认无外发） |

| AC-29 | 手机换到另一个 AP | 同 AC-28：凭据作废，必须重扫 |
| AC-30 | 重新扫码成功 | 连接建立，队列内容自动补发 |

| ID | 场景 | 期望 |
|---|---|---|

| AC-32 | tea_a2 在 8383 运行时启动 a2_share | 两者互不干扰，端口不冲突，tea_a2 行为不变 |

## 6. 非功能需求（NFR）

| ID | 需求 | 指标 |
|---|---|---|
| NFR-01 | 局域网吞吐 | 1 GB 文件 ≥ 5 MB/s（正常 Wi-Fi 环境） |
| NFR-02 | 响应速度 | PC 端启动到可接收 ≤ 1 s；扫码到连接建立 ≤ 5 s；分享到开始传输 ≤ 2 s |
| NFR-03 | 内存 | 传输期间手机端内存增量 ≤ 150 MB（**必须流式，不得整文件进内存**） |
| NFR-04 | 体积 | 手机端 APK ≤ 10 MB；PC 端程序 ≤ 20 MB（含依赖） |
| NFR-05 | 兼容性 | 手机：Android 10 ~ 16（含小米 HyperOS / OPPO / vivo 等有后台限制的 ROM）；PC：Linux / macOS / Windows |
| NFR-06 | 稳定性 | 连续传 20 个文件无崩溃；息屏 30 分钟内传输不中断；App 被杀后队列不丢 |
| NFR-07 | 隐私 | 无遥测、无埋点；剪贴板只在用户主动触发时读取；队列可一键清空；日志只记元数据 |
| NFR-08 | 安全 | 默认仅局域网 + 会话凭据；未配对设备一律拒绝；不自动执行收到的文件 |
| NFR-09 | 可维护 | 一条命令出 APK；一条命令自检；README 含真机验收步骤与已知限制 |
| NFR-10 | 国际化 | UI 文案先中文；不把中文写死在代码里（用字符串资源） |
| NFR-11 | 可观测 | PC 端有结构化日志；手机端有可见的队列与连接状态 |
| NFR-12 | 无 GMS 依赖 | 手机端不依赖 Google Play 服务（国内设备无 GMS），二维码识别必须本地完成 |

## 7. 交互与文案要求

所有文案要**具体、可行动**，禁止「操作失败」「未知错误」这类空话。

|---|---|

### 8.2 工具链要求（另一台机器）

| 项 | 要求 | 备注 |
|---|---|---|
| Android SDK | platform **34** + build-tools **34.0.0**（或更新） | `sdkmanager "platforms;android-34" "build-tools;34.0.0"` |

| PC 端 | Node 20+ 或 Python 3.11+ 均可（仓库已有 ESM 生态） | 写剪贴板：Linux 需 `xclip`/`wl-clipboard`，macOS `pbcopy`，Windows PowerShell |

### 8.3 依赖建议（选型属实现阶段）

| 用途 | 建议 | 约束 |
|---|---|---|
| PC 端生成二维码 PNG | 任意纯 JS/Python QR 库 | 产物必须是 PNG，图案模块足够大便于手机扫 |
| 手机端识别二维码 | 纯本地、无 GMS 的解码库（ZXing 类） | 注意体积；必要时用「系统相册识别 + 短码」兜底 |
| 传输协议 | 自定义轻量 HTTP 协议（**实现阶段定稿**） | 需支持分块、进度、续传、取消 |

### 8.4 命令行约定（PC 端）

| 命令 | 行为 |
|---|---|
| `a2_share` | 进入接收模式，生成二维码 PNG 并打印路径 |
| `a2_share --dir <path>` | 指定接收目录（默认 `~/Downloads/a2_share/`） |
| `a2_share --port <n>` | 指定端口（默认 8899） |
| `a2_share --qr-out <file.png>` | 指定二维码 PNG 输出路径 |
| `a2_share --open` | 生成后自动打开二维码 PNG |
| `a2_share --no-notify` | 关闭桌面通知 |
| `a2_share --history` | 查看接收历史（仅元数据） |
| `a2_share --reset-identity` | 作废会话凭据并重新生成二维码 |
| `a2_share --selftest` | 自检 |

| ID | 风险 | 概率 / 影响 | 缓解 |
|---|---|---|---|
| R-01 | **微信的「用其他应用打开」不一定列出第三方 app**（微信内部文件流常走自有页面） | 高 / 高 | 真机优先验证（AC-03）；不通则给替代路径并写进 README |
| R-02 | Android 10+ 后台读剪贴板受限；Android 12+ 读剪贴板弹系统 toast | 高 / 中 | 只做**用户主动触发**读取；自动推送降为 P1 |
| R-03 | 很多 app 复制图片时给的不是可读 URI（是路径 / HTML / 空） | 中 / 中 | 明确失败提示 + 引导「保存到相册再分享」（AC-11） |
| R-04 | 厂商 ROM 冻结 uid（HyperOS 等）导致息屏后后台断连 | 中 / 高 | 前台服务 + partial wakelock + 省电策略引导页 + 心跳 |
| R-05 | 同一 Wi-Fi 的陌生设备往 PC 投文件（恶意文件） | 中 / 高 | 未配对一律拒绝（FR-S01）+ 落盘隔离 + 不自动执行 |
| R-06 | 二维码被截图外传 = 凭据泄露 | 中 / 高 | 会话凭据 + 离开作用域即作废 + `--reset-identity` 一键作废 + 提示别外传 |
| R-07 | 二维码 PNG 在小屏 / 缩放 / 低对比度主题下扫不出 | 中 / 中 | 图案做足对比度与静区；提供 `--open` 全屏查看与 6 位短码兜底 |
| R-08 | 「离开 Wi-Fi 作用域」判定不准（同 AP 漫游、抖动） | 中 / 中 | 以「Wi-Fi 网络对象变化 + 断开」为判据；提供调试开关定位误判 |
| R-09 | 频繁重扫体验差 | 中 / 中 | 这是明确的产品决策；用「二维码常驻 + 一键扫码入口 + 短码兜底 + 缓存不丢」缓解 |
| R-10 | 缓存占满用户存储 / 被系统清理 | 中 / 中 | 容量护栏 + TTL + 自检清单 + 一键清空 |
| R-11 | 剪贴板缓存残留敏感信息 | 中 / 中 | TTL 24 h + 一键清空 + 不写日志正文 |
| R-12 | 大文件整块进内存导致 OOM | 中 / 高 | 强制流式 + 分块 + 断点续传 |
| R-13 | Windows 防火墙弹窗拦截端口 | 高 / 中 | 首次启动明确提示需放行；README 给放行步骤 |
| R-14 | 二维码识别库体积大 / 依赖 GMS | 中 / 中 | 选纯本地实现；必要时降级为「相册识别 + 短码」 |
| R-15 | 独立 app 缺 tea_a2 的息屏保活经验 | 中 / 高 | 参考 tea_a2 `android/` 已验证做法重写（前台服务 + wakelock + 引导页） |

| R-20 | PC 端写剪贴板在 Wayland / 无 xclip 环境失败 | 中 / 低 | 降级为只存文件并提示（FR-C11） |

## 附录 C：交接说明（给另一台机器上的开发者）

1. **先读本文档**，它是唯一事实源；第 0.3 节是已拍板的决策，不要重新讨论。
2. **建议顺序**：① 传输协议定稿（第 8.3 节留给实现）→ ② PC 端最小闭环（监听 + 二维码 PNG + 落盘）→ ③ 手机端分享目标接入（打通「文件 → PC」）→ ④ 剪贴板 → ⑤ 缓存与补发 → ⑥ 扫码与 Wi-Fi 会话模型 → ⑦ 验收脚本逐条跑第 5 节。
3. **环境**：按 8.2 节准备；JDK 必须是 17（本机默认 `java` 是 25，AGP 8.2 会报错）。
4. **可参考但不要直接依赖**：`tea_a2` 仓库的 `android/`（息屏保活、HyperOS 省电引导、剪贴板 toast 限制）与 `docs/android.md`、`docs/api.md`。
5. **仓库集成**：实现完成后按 8.5 节补横幅 / INDEX / README / npm 脚本。
6. **遇到本文档没覆盖的**：先改本文档（加「变更记录」一行），再改代码。
