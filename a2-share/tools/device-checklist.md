# a2_share · 真机验收清单（AC-01 ~ AC-33）

> 每条都要留证：**时间 / 机型与 ROM / PC 系统 / 命令 / 截图名 / 日志片段（不含内容）**。
> 证据统一放 `a2-share/tools/shots/`（默认不入库，需要入仓库的另存到 `docs/`）。

## 0. 环境准备

| 项 | 要求 | 备注 |
|---|---|---|
| 手机 | Android 10 ~ 16（至少一台 HyperOS / ColorOS） | 无 GMS 也能跑 |
| PC | Linux / macOS / Windows | 与 tea_a2(8383) 可以同时运行 |
| 网络 | 同一 Wi-Fi，**关闭访客网络 / AP 隔离** | 隔离会让 `hello` 超时 |
| PC 端 | `python a2-share/pc/a2_share.py --selftest` 全绿 | 见 §6 |
| 手机端 | `app-release.apk` 已安装，相机与通知权限已授权 | 见 §6 |

## 1. 分享目标与文件传输

| # | 场景 | 步骤 | 期望 | ☐ |
|---|---|---|---|---|
| AC-01 | 5 MB PDF | 系统「文件」app → 选 PDF → 分享 → a2_share | 5 秒内落到 `~/Downloads/a2_share/`，md5 与源一致 | ☐ |
| AC-02 | docx / jpg / zip 各一次 | 分别分享 | 均落地且字节一致 | ☐ |
| AC-03 | 微信里的文件 | 微信 →「用其他应用打开」→ 选 a2_share | 收到且 md5 一致；**若微信不列出 a2_share** → 走替代路径「文件助手 → 系统文件 app → 分享」并记为已知限制 | ☐ |
| AC-04 | 一次分享 3 个文件 | 多选后分享 | 3 个全部落地，文件名不串、不覆盖 | ☐ |
| AC-05 | 中文 / 空格 / emoji 文件名 | 分享 `报告 v2 📄.pdf` | PC 端文件名不乱码、不截断 | ☐ |
| AC-06 | PC 已有同名文件 | 连续分享两次同名文件 | 自动改名 `x (1).pdf`，原文件不变 | ☐ |
| AC-07 | 1 GB 文件 | 分享后观察进度，中途断网再恢复 | 双端有百分比；续传后 md5 一致；记耗时与平均速率（NFR-01 ≥ 5 MB/s） | ☐ |
| AC-08 | 传输中息屏 5 分钟 | 分享 1 GB 后立刻息屏 | 传输仍完成（需已完成 FR-P13 的省电设置） | ☐ |

## 2. 剪贴板

| # | 场景 | 步骤 | 期望 | ☐ |
|---|---|---|---|---|
| AC-09 | 500 字文字 | 复制 → a2_share → 发送剪贴板 | PC 剪贴板逐字相同（含换行、emoji），PC 有桌面通知 | ☐ |
| AC-10 | 剪贴板图片 | 复制一张图 → 发送剪贴板 | 接收目录出现可打开、尺寸正确的 `.png`；开 `--clipboard-image` 时也进 PC 剪贴板 | ☐ |
| AC-11 | 取不到图片 | 复制一个「只有路径字符串」的 app 内容 | 明确提示「取不到剪贴板里的图片，请先保存到相册再分享」，不静默失败 | ☐ |
| AC-12 | 隐私 | 翻 `~/.tea_agent/a2_share/a2_share.log` | 剪贴板正文不出现 | ☐ |

## 3. 配对与连接生命周期

| # | 场景 | 步骤 | 期望 | ☐ |
|---|---|---|---|---|
| AC-13 | PC 启动 | `python a2-share/pc/a2_share.py` | 生成 `~/.tea_agent/a2_share/qr.png`，终端打印路径 + 6 位短码 + 监听地址 | ☐ |
| AC-14 | 扫码 | 手机 a2_share → 扫码连接 PC | ≤ 5 秒显示「已连接 PC-xxx」；PC 终端出现「设备已连接」 | ☐ |
| AC-15 | 短码兜底 | 拒绝相机权限 → 输入短码（并填 PC 地址） | 完成同样的配对 | ☐ |
| AC-16 | 再次分享 | 已配对后分享文件 | **不需要再扫码**，直接传出 | ☐ |
| AC-17 | PC 进程重启 | Ctrl-C 后重新启动 PC | 二维码刷新；手机重连失败并提示「请重新扫码」；扫新码后恢复 | ☐ |
| AC-18 | PC 掉线后恢复 | 临时断网/关掉 PC 再开（不重启进程） | 手机**自动重连成功**，无需重扫 | ☐ |
| AC-19 | PC 换 IP | 换网络后重启 PC | 手机提示「PC 地址可能已变，请重新扫码」；扫新码后恢复 | ☐ |

## 4. 离线缓存与补发

| # | 场景 | 步骤 | 期望 | ☐ |
|---|---|---|---|---|
| AC-20 | 断网分享 3 个文件 | 关 Wi-Fi 后分享 3 个文件 | 提示「已缓存，将在 PC 在线后发送」；PC 启动后自动收到，顺序 FIFO，md5 一致 | ☐ |
| AC-21 | 断网分享 7 个文件 | 同上，7 个 | 只缓存最新 5 个，最早 2 个被淘汰且**有通知**；PC 最终收到 5 个 | ☐ |
| AC-22 | 断网发 12 条剪贴板 | 同上 | 只保留 10 条（剪贴板额度独立，不占文件额度） | ☐ |
| AC-23 | 1.5 GB 文件补发 | 队列里放大文件后让 PC 上线 | 支持续传，md5 一致，双端有进度 | ☐ |
| AC-24 | 剪贴板过期 | 队列里放超过 24 h 的剪贴板 | 自动过期、不再补发，列表标灰；可一键清空 | ☐ |
| AC-25 | 重扫后补发 | 离开 Wi-Fi 期间缓存 5 文件 + 10 剪贴板，重新扫码 | PC 收到 5 个文件 + 10 条剪贴板，无遗漏无重复 | ☐ |
| AC-26 | App 被杀 | 传输中强杀 App 再打开 | 队列内容与状态仍在，未丢 | ☐ |
| AC-27 | 切到蜂窝 | 关 Wi-Fi 用 4G 分享 | 提示「当前非 Wi-Fi，已缓存」；**不发起任何连接**（抓包确认无外发） | ☐ |

## 5. Wi-Fi 作用域

| # | 场景 | 步骤 | 期望 | ☐ |
|---|---|---|---|---|
| AC-28 | 断开再连回同一个 AP | 关 Wi-Fi 1 分钟后连回 | 状态变「已离开 Wi-Fi，需重扫」；此时分享进缓存；**扫码前不会自动连上 PC** | ☐ |
| AC-29 | 换到另一个 AP | 连另一个 Wi-Fi | 同 AC-28，凭据作废，必须重扫 | ☐ |
| AC-30 | 重新扫码 | 扫码成功 | 连接建立，队列内容自动补发 | ☐ |

## 6. PC 端与工程质量

| # | 场景 | 命令 | 期望 | ☐ |
|---|---|---|---|---|
| AC-31 | 自检 | `python a2-share/pc/a2_share.py --selftest` | 逐项打印通过/失败，全通过退出码 0 | ☐ |
| AC-32 | 与 tea_a2 共存 | tea_a2 在 8383 运行时启动 a2_share | 两者互不干扰，端口不冲突 | ☐ |
| AC-33 | 全新安装 | 卸载后重装 APK，走完「扫码 → 分享 → PC 收到」 | 不依赖 tea_a2；APK ≤ 10 MB（实测 4.3 MB） | ☐ |

```bash
npm run a2share:e2e       # PC 端 19 项集成闭环
npm run a2share:test      # 手机端 51 项 JVM 单测
```
